# 科研探索边带 · dsh-sci-sideband

一条给 **DeepSeek Harness** 用的科研探索边带。你只需要给出一个**研究兴趣与目的**，它就会从默认开放源（arXiv、OpenAlex、Crossref、Europe PMC、DOAJ、Semantic Scholar）自动发现相关论文与内容，在后台读成可核查的证据，再基于这些证据给出**实验设计建议**和一篇连贯的**综述论述**。不需要先拆题目。

> 它做的是「发现、管理、探索、沉淀、建议」；**不执行实验，也不处理原始实验数据**。实验建议只是设计参考，执行前需要人工论证、预注册与伦理审查。开放获取内容会抓取全文；付费墙期刊只取元数据/摘要，全文取决于是否开放。

## 它解决什么问题

科研中最费时间的不是写一段文字，而是：

- 我对这个方向感兴趣，但资料散在论文、预印本、项目页、专利里；
- 我已经有一些结果，但不知道下一步该补什么实验；
- 我读了很多，却说不清哪些结论有证据、证据在什么条件下成立；
- 写综述时，引用和数据对不上。

科研探索边带把这条链路固定为：

```
科研项目 / 研究兴趣 + 已有成果
        ↓
自动发现：arXiv · OpenAlex · Crossref · Europe PMC · DOAJ · Semantic Scholar
        ↓
科研内容（论文 / 预印本 / 报告 / 项目页 / 专利 / 数据集）
        ↓
后台探索：抓取 / 摘要 → 模型分析 → 证据沉淀（指标 / 结论 / 条件 / 原文引文）
        ↓
实验建议（可检验的假设与设计） + 综述论述（带引用的连贯文章）
```

## 功能

- **科研项目**：标题、研究兴趣/目的、已有成果/当前进展、领域、状态。
- **默认源自动发现**：创建项目后可直接从 arXiv、OpenAlex、Crossref、Europe PMC、DOAJ、Semantic Scholar 检索；每源默认取 100 条候选，**不按固定条数截断**，而是用与目的/检索短语的相似度评分（默认阈值 0.3，可调 0.2–0.6）决定是否加入，单次最多 200 条。开放获取内容抓全文，付费墙期刊只取元数据/摘要。发现记录按 DOI/标题去重，可随时重跑。中文研究兴趣会先用当前模型扩写成英文检索短语；没有模型时按原文检索。
- **按引用深度探索**：对已分析内容追踪其参考文献与被引文献（OpenAlex，Semantic Scholar 兜底），按相关性过滤后加入并分析一层；可对关键论文反复扩散，逐步加深。
- **科研内容管理**：除自动发现外，也可手动添加 URL、DOI 或粘贴原文；支持论文、预印本、报告、数据集、项目页、专利、博客等类型。
- **后台探索**：逐条抓取正文（或摘要），只抽取「解决的问题、提出的方法、关键成果、批判性局限、关键公式」五项；关闭面板不中断，重载后会把中断的探索标出来。
- **自动知识库**：每条已分析内容会自动写成 `wiki/<sourceId>.md`（Frontmatter + 摘要 + 分析 + 证据），并生成 `wiki/index.jsonl`，可直接给 LLM/RAG/本地 wiki 使用。
- **长期扫描**：项目可开启自动扫描（12/24/72/168 小时），DSH 运行期间每 15 分钟检查一次到期项目，自动发现并分析新内容。
- **证据在后台使用**：抽取的证据不再单独展示，而是由实验建议与综述在内部使用；每条仍保留来源与引文，便于生成结果时核查。
- **实验建议**：独立的科研 proposal 流程。在「想探究的问题」里写下基于研究目的的定向问题（可附资源限制，例如只有 1 台 A100 80GB、每周 20 GPU 小时），生成 1–6 条精简 proposal：研究问题与目标、可证伪假设、方法与步骤、变量/对照、读端、资源与时间线、风险与备选、预期结果；每条明确标注“建议不是实验结果”。
- **综述论述**：把项目目的、已有成果、已分析内容与证据组合成摘要、引言、相关研究、方法、结果与讨论、结论与展望、参考文献；可复制 Markdown 或下载 `.md`。
- **无模型兜底**：没有可用模型或模型失败时，明确标注并退回本地规则/模板，流程不中断。
- **Agent 工具**：`sci_task`、`sci_source`、`sci_status`、`sci_data`、`sci_experiment`、`sci_report`，与面板共用同一套动作层。

## 科研 Superagent

仓库里的 `superagent/` 是一个独立的 agent preset bundle。它把主会话变成调度器，并通过 `dsh-mini-superagent` 把任务派给四个独立子会话：

```text
Research Supervisor
  ├─ grabber   发现 / 引用扩散
  ├─ analysis  逐篇五段式分析
  ├─ reviewer  用 sci_review 清洗证据、核验引用、审核报告
  └─ writer    基于清洗后证据写实验计划、目的与意义
```

使用前：

1. 安装 `dsh-mini-superagent`（提供 `dispatch_*` 工具）。
2. 安装 `superagent/` bundle。
3. 新建会话时选择 **科研 Superagent** preset。

Reviewer 是独立子会话，不共享调度器上下文；`sci_review` 本身用隔离 LLM 调用、`temperature=0` 执行审核。调度器负责路由与合并报告，不亲自做 grabber/analysis/reviewer/writer 的工作。

## 安装

### 本地目录安装

1. 打开 **设置 → 插件 → 添加插件**，选择本仓库目录（包含 `package.json` 与 `cordis.patch.yml`）。
2. 安装后左侧栏出现 **科研探索边带** 图标。

也可以在 DSH 会话里让插件管理器安装本地目录。

### 从插件市场安装

把本仓库的市场索引地址加入 **设置 → 插件 → 发现 → 索引源**：

```
https://raw.githubusercontent.com/Dzy-HW-XD/dsh-sci-sideband/main/market/index.json
```

索引使用 `format: 1`，版本源固定到发布 commit；用户可在「发现」里一键安装。

## 使用

1. 新建科研项目，写清**研究兴趣/目的**和**已有成果/当前进展**。
2. 勾选「创建后自动从默认源发现并分析」（默认开启），或稍后在「科研内容」页点「从默认源发现并分析」；可设每源检索深度（20/50/100）与相似度阈值（0.2–0.6）。
3. 边带会检索、去重、加入内容，并自动开始后台分析。
4. 需要更深时，在「科研内容」点「按引用深度探索」：沿已分析论文的参考文献/被引文献再走一层，按相关性过滤后继续分析。
5. 在「实验建议」的「想探究的问题」里写下定向问题（资源限制可附在同一段），再点「生成实验建议」，拿到精简 proposal。
6. 在「综述论述」点「生成综述论述」，阅读、复制或下载 Markdown。

也可以跳过自动发现，手动添加 URL/DOI/原文；不需要先建题目。

## 数据与隐私

- 数据文件：`$DSH_HOME/sci-sideband/data.json`（默认 `~/.dsh/sci-sideband`；可用 `DSH_SCI_SIDEBAND_DATA` 或插件 `config.dataDir` 覆盖）。
- 自动知识库：`$DSH_HOME/sci-sideband/wiki/`，每条内容一个 Markdown 文件，另有 `index.jsonl`。
- 科研内容的 URL 通过宿主 `web` 服务抓取；正文、研究兴趣与已有成果会发送给「设置 → 模型」中配置的对话提供方。
- 插件被禁用后不再加载，已保存数据保留；删除插件不会自动删除数据目录。
- 插件不执行实验、不采集实验设备数据、不处理原始实验数据。

## 架构

```
index.js                Host 入口：注册 Connection 精确路由 + tools
lib/lab.js              动作层：项目/内容/发现/探索/证据/实验建议/综述；后台队列
lib/discovery.js        默认开放源检索与去重（arXiv/OpenAlex/Crossref/Europe PMC/DOAJ/Semantic Scholar）
lib/analysis.js         抓取、模型分析、规则兜底、综述综合、实验建议
lib/store.js            原子 JSON 存储（串行写队列）
lib/tools.js            Agent 工具（调用同一动作层）
client.js               AMD 客户端面板（sidebar.panellist + main）
market/index.json       插件市场索引（format 1）
```

数据通道：`ctx.get('connection').rpc.call('/api', 'sci-sideband/call', { action, args })`，宿主在 `/api/sci-sideband/call` 注册精确 Fetch 路由，继承 Connection 的鉴权与来源信任栅栏。

## 限制

- 自动发现依赖各开放源的公开 API；Crossref/OpenAlex 能提供主流期刊的元数据/摘要，但**付费墙全文不会自动获得**，只能分析摘要或由你粘贴全文。
- 发现质量取决于研究兴趣的表述；中文兴趣在英文源上的召回可能偏低，建议在标题/目的里同时给出英文关键词。
- 内容抓取依赖目标站点可匿名访问；登录墙/JS 渲染页需要直接粘贴原文。
- 模型分析/建议质量取决于所选模型；规则/模板兜底只适合作为初筛，引用与实验设计前必须人工核对。
- 综述中的引用只来自边带已登记的内容；模型仍可能误用编号，生成后请核对参考文献。
- 综述与实验建议目前是同步等待（有防重入与忙碌提示，最长约 6 分钟）；后台探索暂无「停止」按钮，关闭面板不会中断。
- 单文件 JSON 存储，内容很多时没有分页/压缩。
- 实验建议不是实验结果，不构成伦理、安全或统计功效方面的保证。

## 开发

```powershell
node scripts/selftest.mjs
```

自测使用模拟的 `web` / `llm` 服务，覆盖：项目、默认源发现与去重、后台分析、摘要回退、自动证据、运行中新增内容续跑、「仅保存」内容不被误分析、显式单条分析、证据编辑、模型综述、无模型兜底、级联删除。

### 生成市场索引

```powershell
node scripts/make-market-index.mjs --commit <40位commit>
```

索引会写入 `market/index.json`，并把版本源固定到该 commit。发布顺序：先提交代码并打 tag，再生成并提交索引。
